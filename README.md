# Alpine Linux 安装教程

本教程用于在当前临时系统中配置网络，然后下载并运行 `vnc.sh` 安装脚本。

安装脚本执行完成后，设备可能会重新启动并进入 Alpine Linux。

> ⚠️ **重要提醒**
>
> - 安装系统可能会清除硬盘中的原有数据，请提前备份重要文件。
> - 请确认当前设备确实需要重装系统。
> - 不要在保存有重要数据的设备上直接测试。
> - 以下命令需要在具有 `root` 权限的终端中执行。
> - 安装过程中不要断电、关机或强制终止脚本。

---

## 第一步：查看网卡名称

先执行：

```sh
ip link
```

在输出中找到实际使用的有线网卡。常见名称包括：

- `eth0`
- `ens3`
- `enp1s0`

下面的教程假设网卡名称是 `eth0`。

如果你的网卡名称不是 `eth0`，请将后续命令中的 `eth0` 替换成实际名称。

---

## 第二步：启用网卡

执行：

```sh
ip link set eth0 up
```

这条命令用于启用名为 `eth0` 的网卡。

如果命令提示找不到 `eth0`，请返回第一步，确认真实网卡名称。

---

## 第三步：自动获取网络配置

执行：

```sh
udhcpc -i eth0
```

该命令会通过 DHCP 自动获取网络配置，包括：

- IP 地址
- 默认网关
- DNS 等信息

如果成功，通常会看到类似内容：

```text
lease of 192.168.1.100 obtained
```

如果一直无法获取地址，请检查：

- 网线是否已经连接；
- 路由器或上级网络是否启用了 DHCP；
- 网卡名称是否正确；
- 如果是虚拟机，虚拟网络适配器是否已经启用；
- 当前网络是否要求使用静态 IP。

---

## 第四步：检查 IP 地址

执行：

```sh
ip addr show eth0
```

也可以使用简写：

```sh
ip a
```

在输出中寻找类似内容：

```text
inet 192.168.1.100/24
```

出现 `inet` 地址通常表示设备已经获取到 IPv4 地址。

> `127.0.0.1` 是本机回环地址，不能用它判断外部网络是否连接成功。

---

## 第五步：测试网络连接

先测试是否能够连接公网 IP：

```sh
ping -c 3 1.1.1.1
```

然后测试脚本服务器的域名：

```sh
ping -c 3 linux.7742.cc.cd
```

如果看到类似下面的响应，说明网络连接正常：

```text
64 bytes from ...
```

### 如何判断故障

- 两个地址都无法连接：通常是网卡、DHCP、网关或物理网络问题。
- `1.1.1.1` 可以连接，但域名不能连接：通常是 DNS 配置问题。
- 两个地址都可以连接：网络基本正常，可以继续下载安装脚本。

> 某些服务器可能会禁用 Ping。域名无法 Ping 通不一定表示网站无法访问，最终还要以脚本能否成功下载为准。

---

## 第六步：下载安装脚本

建议先下载脚本，不要在同一条命令中立即执行：

```sh
busybox wget -O /tmp/vnc.sh https://linux.7742.cc.cd/vnc.sh
```

参数说明：

- `busybox wget`：使用 BusyBox 提供的下载工具；
- `-O /tmp/vnc.sh`：将下载内容保存到 `/tmp/vnc.sh`；
- `https://linux.7742.cc.cd/vnc.sh`：安装脚本的下载地址。

下载完成后，检查文件是否存在：

```sh
ls -l /tmp/vnc.sh
```

如果文件不存在、大小为 `0`，或者下载过程中出现错误，请不要继续执行。

---

## 第七步：检查脚本内容

执行脚本前，建议先查看内容：

```sh
cat /tmp/vnc.sh
```

如果系统中有 `less`，也可以分页查看：

```sh
less /tmp/vnc.sh
```

请确认下载到的是 Shell 脚本，而不是以下内容：

- 网站首页；
- `404 Not Found` 错误页面；
- HTML 页面；
- 登录或验证页面；
- 内容为空的文件。

Shell 脚本开头通常类似：

```sh
#!/bin/sh
```

或者：

```sh
#!/bin/bash
```

> ⚠️ 该脚本可能会修改磁盘分区、文件系统、引导配置和系统文件。只有确认脚本来源可信、内容符合预期后，才能继续执行。

---

## 第八步：运行安装脚本

确认脚本下载正确并检查无误后，执行：

```sh
sh /tmp/vnc.sh
```

脚本运行期间请注意：

1. 不要关闭设备；
2. 不要断开电源；
3. 不要随意按 `Ctrl+C` 终止脚本；
4. 保持网络连接正常；
5. 仔细阅读终端中显示的提示和错误信息。

---

## 第九步：等待安装完成

脚本执行完成后，设备可能会自动重新启动。

如果脚本明确提示安装成功，但设备没有自动重启，可以根据实际提示执行：

```sh
reboot
```

> 不要在脚本仍然运行或安装尚未完成时强制重启。

设备重新启动后，检查是否成功进入 Alpine Linux。

---

## 快速执行版

如果你已经完成以下确认：

- 网络连接正常；
- 脚本地址正确；
- 已经查看过 `vnc.sh`；
- 确认脚本内容安全；
- 确认设备中的重要数据已经备份；

可以使用下面的命令下载并执行脚本：

```sh
busybox wget -O /tmp/vnc.sh https://linux.7742.cc.cd/vnc.sh && sh /tmp/vnc.sh
```

其中 `&&` 的意思是：

> 只有前面的下载命令执行成功，才会继续运行后面的安装脚本。

第一次安装时，仍然建议按照前面的详细步骤逐条执行。

---

## 常见问题

### 1. 找不到 `eth0`

执行：

```sh
ip link
```

找到真实网卡名称，然后替换命令中的 `eth0`。

例如，真实网卡名称是 `ens3`：

```sh
ip link set ens3 up
udhcpc -i ens3
ip addr show ens3
```

### 2. `udhcpc` 一直获取不到地址

检查：

- 网线是否连接；
- 路由器是否提供 DHCP；
- 网卡名称是否正确；
- 虚拟机网络适配器是否启用；
- 当前网络是否必须配置静态 IP。

### 3. 公网 IP 能访问，但域名无法访问

依次执行：

```sh
ping -c 3 1.1.1.1
ping -c 3 linux.7742.cc.cd
```

如果 `1.1.1.1` 可以访问，但域名不能访问，通常是 DNS 配置问题。

### 4. 脚本下载失败

先删除下载失败或不完整的文件：

```sh
rm -f /tmp/vnc.sh
```

然后重新下载：

```sh
busybox wget -O /tmp/vnc.sh https://linux.7742.cc.cd/vnc.sh
```

最后检查文件：

```sh
ls -l /tmp/vnc.sh
cat /tmp/vnc.sh
```

### 5. 下载后显示的是 HTML 或错误页面

这通常说明：

- 脚本地址不正确；
- 网站发生了跳转；
- 服务器返回了错误页面；
- 网站要求登录或进行安全验证。

此时不要执行 `/tmp/vnc.sh`。请先确认下面的地址能够直接返回脚本文本：

```text
https://linux.7742.cc.cd/vnc.sh
```

### 6. 安装失败怎么办

先不要反复运行脚本，也不要立即重启。

建议记录或拍照保存以下信息：

- 完整错误信息；
- 失败前执行到哪一步；
- `ip a` 的输出；
- `ip route` 的输出；
- 设备或虚拟机的类型；
- 磁盘中是否保存有重要数据。

确认失败原因和再次执行的安全性后，再决定是否重试。

## 完整命令清单

```sh
# 1. 查看网卡名称
ip link

# 2. 启用 eth0 网卡
ip link set eth0 up

# 3. 通过 DHCP 获取网络配置
udhcpc -i eth0

# 4. 查看 IP 地址
ip a

# 5. 测试公网连接
ping -c 3 1.1.1.1

# 6. 测试脚本服务器域名
ping -c 3 linux.7742.cc.cd

# 7. 下载安装脚本
busybox wget -O /tmp/vnc.sh https://linux.7742.cc.cd/vnc.sh

# 8. 检查下载的文件
ls -l /tmp/vnc.sh
cat /tmp/vnc.sh

# 9. 确认安全后运行脚本
sh /tmp/vnc.sh
```
